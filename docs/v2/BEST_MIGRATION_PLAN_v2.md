## Поэтапный перенос без потерь

1. Владелец отзывает ключ; проверяются доступы. Сохраняется контролируемая резервная копия репозитория и исходных данных с ограниченным доступом. Она тоже содержит прежние секреты и не должна стать общедоступным ZIP. История не переписывается в этой фазе без координации.
2. Создать manifest: source repository/commit, file checksum, content checksum, counts, schema version, original record position/ID и locator. Legacy occurrence ID = источник + позиция + исходный hash, поэтому две записи ID 60 не сталкиваются. Новый UUID назначается каждому occurrence.
3. Импорт в staging/draft, не published. Сохранять локали и исходные payload без сокращения. Секретные конфигурационные поля не входят в учебный payload. Manifest фиксирует намеренно исключённые пути `access` и credentials; это исключение секретов, не потеря образовательных материалов.
4. Сверить количество, состав и хэши экспортированного обратно content. Покомпонентная разница разрешена только по зарегистрированному преобразованию. Два повторных запуска импорта дают те же записи и mapping, без удвоения. Неподдержанный формат останавливает импорт, не молча пропускает вопрос.
5. Назначить статусы замечаний/компетенций/источников; решения по дублю, ключам, безопасности и переводам принимает автор. Исправленная версия связана с исходной. Оригинал остаётся доступным уполномоченному редактору для сравнения.
6. Разработать API и адаптеры рядом с legacy. Для сравнения оценивания использовать синтетические данные и согласованные policy; старую ошибку не закреплять как норматив ради совпадения теста. Не запускать второй poller на production-токене.
7. Отдельный test bot и БД: проверить новые меню, полномочия, завершение и recovery. Shadow-сравнение не отправляет пользователю дубли и не записывает в production Sheets.
8. Перед переключением уведомить о границах переноса, приостановить создание старых попыток, дать завершить активные или явно пометить как legacy/unrecoverable. Текущие sessions только в памяти — автоматическое восстановление после остановки не гарантируется.
9. Отдельно согласовать импорт исторических Sheets-строк: наличие таблицы и её данные не проверены. Импортированные итоги помечаются `legacy_result_unverified`, без выдумывания отсутствующих ответов, policy и практики. Не превращать такие строки в подтверждённые новые сертификаты.
10. Переключить один канал доставки, сверить новые записи/уведомления и резервную копию. Rollback возвращает проверенную версию приложения и совместимую БД; не теряет уже принятые ответы и не стирает законные завершённые попытки.

## Приёмка миграции

Сохранены все учебные source occurrences, все локали и ссылки; для каждого преобразования есть mapping. Повторный импорт идемпотентен. Дубль явно виден и имеет решение, а не исчезает. Ни один приватный ключ/код не скопирован в новый frontend/public content. Старый бот не снят без проверенного нового маршрута. Выполнен restore, в котором совпадают количества попыток/ответов/профилей и ссылки на файлы.

Досье, production-логи, права и текущие данные Google Sheets, условия хостинга, внешние документы по методике и лицензии медиа остаются внешними входами. Их отсутствие не восполняется догадками; зависимые работы отмечены в [roadmap](BEST_ROADMAP_v2.md).
