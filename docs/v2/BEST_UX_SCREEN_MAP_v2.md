# B.E.S.T. Academy — маршруты, экраны и дизайн v2

Статус: информационная архитектура и текстовые wireframes для утверждения D-08/D-13, не готовый UI. Реализация — после приёмки прототипов. Контекст: [продукт](BEST_PRODUCT_VISION_v2.md), [архитектура](BEST_ARCHITECTURE_v2.md).

## Пользовательские маршруты

1. Гость → обзор → разрешённый пример урока → приглашение/вход → выбор своего профиля → «Моя академия». Demo не подменяет весь учебный курс.
2. Ученик → продолжить урок → цель/предварительные навыки/безопасность → объяснение и схема → формативное задание → практика под допустимым контролем → сохранённый результат → следующее назначение. Повторное открытие восстанавливает серверный checkpoint.
3. Пользователь Mini App → серверная проверка initData → существующая связь или подтверждённое связывание аккаунта → тот же маршрут. Отказ проверки не выдаёт доступ. В браузере доступен независимый вход.
4. Родитель → подтверждённая связь с ребёнком → разрешения/учебные назначения/прогресс → запрос инструктору в защищённом канале. Контакты посторонних и открытый поиск детских профилей отсутствуют.
5. Инструктор → назначенные группы → ученик → план занятия → отметки навыков и безопасные комментарии → рекомендация → уведомление по разрешённому каналу. Прямой URL чужого ученика не предоставляет доступ.
6. Экзаменуемый → допуск и правила → подтверждение начала → серверная попытка → задания/сохранение → проверка обязательных ответов → отправка → результат теории → отдельная практическая аттестация → внутренний итог, если выполнены условия.
7. Редактор → черновик → источники/медиа → методическая проверка → безопасность → переводы и проверка → предпросмотр → утверждённая публикация. Изменение опубликованного материала создаёт новую версию.
8. Экзаменатор → назначение → протокол по опубликованной рубрике → наблюдаемые критерии/доказательства → подтверждение → право на итоговый статус, если полномочия и требования действуют.

## Wireframes для первой приёмки

**Моя академия, телефон:** верхняя строка с профилем/настройками; крупная карточка «Продолжить Balance» с целью; четыре подписанных индикатора B/E/S/T; одно следующее действие; практическое назначение; история. Нижняя навигация: Академия, Маршрут, Практика, Прогресс. Проценты прочитанного и проверенные практические навыки обозначаются раздельно.

**Урок:** заголовок/цель/предпосылки; заметный блок безопасности до интерактива; поэкранные разделы с сохранением; схема рядом с текстовой альтернативой; практическое задание и критерий освоения; контрольные вопросы; итог. Для ребёнка меняются язык подачи и плотность, не физические критерии безопасности.

**Интерактив:** формулировка; SVG с подписанными объектами; кнопки/слайдер с клавиатурой вместо drag-only; «Проверить»/«Сбросить»; объяснение; постоянная подпись «Учебное упрощение». Никакого автоматического заключения о технике реального ученика по движению картинки.

**Результат:** отдельно «Теория», число баллов, максимум, процент, выполненные обязательные условия и практика; причина отсутствия итогового допуска. Не показывать визуально «сертифицирован», когда сохранён только учебный тест.

**Studio:** список разрешённых учеников → карточка → назначение/наблюдение. Нет глобального каталога детских профилей. Редактор видит статус ревью и конкретные причины блокировки публикации.

## Дизайн-система для согласования

Предлагаемые роли цветов: фон `#F6F8FB`, поверхность `#FFFFFF`, текст `#17263A`, основной акцент `#174C73`. Финальные сочетания проходят измерение контраста, эти значения не считаются заранее принятыми. Сетка 4/8 px, умеренная ширина текста, сенсорные цели предпочтительно 44×44 CSS px, видимый focus. Проверить WCAG 2.2 AA, масштаб 200%, reflow на ширине 320 CSS px. Уважать reduced-motion, запрет autoplay и обязательной анимации для ответа.

Микроанимации поясняют действие, не создают обязательный тайминг. Для B/E/S/T использовать букву + название + цвет. Достижения не сравнивают детей публично и не подталкивают к скорости/риску. Визуальные файлы и motion-прототипы создаются после утверждения направления, а не считаются уже готовыми.

## Telegram UX

Сервер хранит ссылку на актуальное главное сообщение и revision навигации. Callback содержит короткий непрозрачный ID действия, соответствующий серверному разрешению; старое действие не интерпретируется через хрупкий split ID. Каждый callback подтверждается, затем проверяются субъект, актуальность и права. При устаревании — безопасное сообщение и актуальное меню. При невозможности edit создаётся новое меню, старая клавиатура деактивируется где это допустимо. Пользовательская полезная переписка не удаляется.

`/start` восстанавливает разрешённый профиль и предлагает продолжить серверную попытку; не обнуляет экзамен. Длинные материалы открываются в Mini App/вебе, краткий результат остаётся в боте. Новое меню не маскирует несовместимость незавершённой версии экзамена.

Обязательны UX-03/05/06/07/10/11/12/13/18/19/24/26/27/28/31 и ограниченные UX-40/41; часть Studio может быть объединена в небольшие формы с теми же проверками прав. UX-14…17 и 21/22 — после D-05/D-06/D-09. UX-25 — после D-04. Редакционные публикации пилота допускают контролируемый административный процесс вместо готового визуального редактора, но должны сохранять источник, версию и автора проверки. Это явно ограниченный этап, не утверждение готовности всех экранов.
