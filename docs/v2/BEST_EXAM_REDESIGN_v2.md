## Отдельные режимы

| Режим | Обратная связь | Итог |
|---|---|---|
| Тренировка | Объяснение после ответа, разрешённый повтор | Учебный прогресс, без квалификации |
| Тематическая проверка | По правилам программы | Освоение темы, не профессиональный допуск |
| Теоретический экзамен | По утверждённой политике раскрытия | Отдельный результат теории |
| Практическая аттестация | Наблюдение уполномоченного экзаменатора | Протокол практики |
| Внутренний статус B.E.S.T. | Выполнение всех требований версии | Внутренний статус, не государственная лицензия |

Формативный Balance-пилот использует первый режим с явной маркировкой. Это не означает сокращение полного экзамена.

## Версия задания

Стабильный `question_id` и отдельный `question_version_id`; компетенции, аудитория, сложность, source references, тип ответа, текст по локалям, explanation, критичность и её основание, scoring rule, медиа, публикационный статус. Типы: single choice, multiple choice, ordering, matching, распознавание на изображении и ситуационный выбор. Числовые/открытые ответы добавляются при принятой рубрике и необходимости ручной оценки, не на основе произвольного сравнения строк.

Каждый вариант имеет неизменяемый ID, а не только индекс. Ученик получает порядок ID без признака правильности; сервер сохраняет именно выданный порядок. При перемешивании меняется представление, не ключ. Варианты «всё перечисленное» должны ссылаться на смысл, а не номера; при неустранимой зависимости перемешивание вариантов для такой версии запрещается и фиксируется.

Связанные части кейса имеют общий versioned context и порядок. Перемешивается кейс как группа только там, где это не ломает предпосылки. Отдельная выдача части «2/5» без контекста не допускается. Сходство формулировок выявляется технически, а смысловое дублирование решает редактор/автор.

## Blueprint и политика экзамена

`ExamVersion` фиксирует набор компетенций, обязательные задания/группы, допустимую выборку, веса и max_score. `PolicyVersion` отдельно фиксирует шкалу уровней, время, пересдачу, completeness, critical, раскрытие ответов, требуемую практику и полномочия для утверждения. Публикация невозможна при неопределённом обязательном параметре. Старые попытки не пересчитываются по новой policy задним числом; пересмотр оформляется отдельным аудируемым решением.

Варианты шкалы для D-05:

| Вариант | Следствие | Нерешённый вопрос |
|---|---|---|
| A. Абсолютные баллы: PRO 100–120, Standard 85–99, Trainee 70–84 | Близко к тексту legacy-гайда | Нужно утвердить максимум 120, полноту банка, практику и допуск; нельзя просто удалить дубль без решения |
| B. Проценты: границы утверждает автор | Не зависят напрямую от количества заданий | PRO не обязан равняться 100%; перенос нынешней ошибки как нормы недопустим |
| C. Профиль компетенций + общий результат | Можно требовать минимум по каждому разделу и critical | Требует новой валидации blueprint и рубрик; нельзя скрыто добавить в существующий экзамен |

Рекомендация: хранить баллы и проценты раздельно, применять версионируемые policy и обязательность всех критических компетенций. Конкретные числа остаются открытыми до досье и ответа автора. 60 минут и 30 дней — кандидаты из legacy, а не принятые новые нормативы.

## Жизненный цикл попытки

`created → in_progress → submitted → graded`.

Из `in_progress` допустимы `expired`, `abandoned`, `invalidated`; из `expired` оценка разрешена только если опубликованная policy явно описывает это, выполнены требования полноты и результат не выдаёт запрещённый статус. Терминальные состояния неизменяемы, исправление — отдельная процедура. Пауза интерфейса не останавливает серверный таймер, если это отдельно не разрешено policy.

При создании сервер сохраняет exam/policy versions, выданные question/case versions, обязательность, порядок вопросов и вариантов, locale, max_score, начало/deadline. Каждый ответ имеет server timestamp, revision и idempotency ID. Возврат после рестарта восстанавливает эти данные, а не собирает новую случайную выборку.

Submit транзакционно проверяет: владельца и допуск, состояние/revision, срок, все обязательные ответы, валидность типов, наличие критических частей, правило оценки, практические требования для соответствующего документа. Досрочный выход сохраняет попытку как незавершённую/abandoned; квалификационный уровень за неполный обязательный набор не присваивается. Клиентская кнопка не является проверкой полноты.

Пропуск обязательного critical-задания не считается правильным. Критическая ошибка фиксируется событием и определяет непрохождение в соответствии с принятой policy. Возможность закончить позже в учебном режиме не меняет проваленную экзаменационную попытку и не стирает событие. Момент сообщения о critical и правила продолжения утверждаются D-06.

Обновления сериализуются блокировкой/optimistic revision в БД. Повтор того же события не начисляет балл второй раз. Запоздалый ответ после submit не меняет результат. Для таймера используется время сервера; часовой пояс меняет только отображение.

## Практическая аттестация

Утверждённая рубрика содержит наблюдаемые критерии B/E/S/T, среду, ограничения, допустимые упражнения, критические события и право экзаменатора. Протокол хранит дату, условия, версию рубрики, проверенные критерии, комментарии, основания решения и при необходимости разрешённые доказательства. Checkbox «практика пройдена» без источника/полномочий недостаточен.

Оценки интерфейсного SVG не становятся оценками реального движения. Для ребёнка дополнительно действуют утверждённые ограничения участия представителя, хранения изображений/видео и видимости протокола. Официальная профессиональная квалификация не выводится из внутреннего статуса платформы.

## Сертификаты и раскрытие результатов

Разделить документы об обучении, теории и практике. Итоговый внутренний документ выдаётся только при выполненных основаниях D-09, с номером, датой, версией требований, шаблоном, status и возможностью отзыва/замены. Повтор запроса возвращает тот же документ либо новую версию исправления, не второе основание выдачи.

Сохранение результата происходит до генерации/отправки. PDF/PNG с кириллическим шрифтом — артефакт, не единственный журнал. Экспорт Sheets и Telegram-доставка могут повторяться безопасно. Публичная проверка не раскрывает детский профиль или неутверждённые персональные поля. Объяснения и ключи выдаются по policy: учебный режим и защищённый экзамен могут иметь разный момент раскрытия.

## Методическая приёмка

Для каждого задания: источник, однозначность, ключ, объяснение, соответствие компетенции, локализация, безопасность distractors и основание critical. Разрешить противоречия геометрии плуга, контекста Steering, усталости, подъёмников/помощи при травмах из аудита. Структурно корректный индекс 0–3 не подтверждает истинность ответа. До этой приёмки импортированный банк остаётся источником для сверки, не автоматически утверждённым экзаменом Academy.
