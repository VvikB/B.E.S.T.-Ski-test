# B.E.S.T. Academy — этапы, backlog, зависимости и трудоёмкость v2

Статус: предварительный план для утверждения. Оценка не является календарным обещанием. [Реестр решений](BEST_DECISION_REGISTER_v2.md), [приёмка](BEST_QA_ACCEPTANCE_v2.md), [миграция](BEST_MIGRATION_PLAN_v2.md).

## Принципы очередности

P0 — отзыв ключа и защита источников; P1 — корректность доступа, сохранения, экзамена и основных маршрутов; P2 — полнота обучения/контента/Studio; P3 — оптимизация и расширение после измерений. Порядок фаз соответствует ТЗ, но приёмка схемы экзамена происходит заранее, а выдача статусов внедряется в фазе 5. Старый банк сохраняется уже в фазе 0, а не ждёт релиза экзаменов.

Вопросы к автору не блокируют независимые проектные работы. Они блокируют соответствующую публикацию/реализацию нормативов. Нельзя заменить отсутствие решения «разумным» числовым порогом.

## Этапы и диапазоны

Единица — человеко-дни инженерной работы с необходимыми автоматическими тестами, ревью и технической документацией. Предположения: один опытный full-stack разработчик, знакомый с Python/React, доступность автора и отдельного дизайнера/предметного проверяющего. Производство профессионального видео, массовая редактура/перевод всего банка, юридическая экспертиза, ожидание внешнего доступа и массовое ручное тестирование не включены. При ином составе команды диапазон пересматривается.

| Фаза | Работы | Инженерная оценка | Зависимость / критерий выхода |
|---|---|---:|---|
| 0 | Инвентаризация, безопасные копии, отзыв ключа владельцем, фиксация требований | 3–6 | Досье запрошено, P0 подтверждён, baseline и manifest приняты |
| 1 | Архитектура, wireframes/прототипы, модель данных, проект регламента | 8–14 | D-01…D-09 рассмотрены; UX и schema согласованы в нужной части |
| 2 | Backend, PostgreSQL, auth/RBAC, миграции, базовая PWA и Telegram adapter | 20–35 | Персональный вход, права, сохранение/restart/restore, тестовый канал |
| 3 | Полный Balance-урок, 3 принятые схемы, тренировочный маршрут, небольшой Studio | 10–18 | QA пилота; автор принял инструкции/медиа; 3–5 взрослых прошли маршрут |
| 4 | E/S/T, библиотека безопасности, программы/локали/медиа | 20–40 | Материалы прошли методическую и безопасностную приёмку |
| 5 | Версионируемые экзамены, практика, документы, проверка/отзыв | 20–35 | Policy утверждены, обязательность/critical/повторы и допуски проверены |
| 6 | Полный кабинет, группы, визуальный редактор и расширенный пилот | 25–45 | Все роли и публикационные переходы покрыты; права проверены |
| 7 | Нагрузочные измерения, оптимизация, доступность, расширение | 10–20 | Достижимые эксплуатационные требования подтверждены |

Итого арифметически 116–213 инженерных человеко-дней при перечисленных предположениях. Это не срок «через N дней» и не оценка полной стоимости проекта. Дополнительно предусмотреть ориентировочно 15–30 человеко-дней UX/дизайна и 20–40 ручной/исследовательской QA-работы, не дублирующей включённые developer tests. Предметная проверка каждого задания/языка и производство медиа оцениваются отдельно после получения досье и материалов.

До закрытого пилота: ориентир фаз 0–3 = 41–73 инженерных человеко-дня, плюс дизайн и предметная работа. Это подготовительный диапазон; после согласования прототипов и пробного развёртывания пересчитать по фактическому backlog. Нулевые обязательные расходы на хостинг не означают отсутствие трудозатрат разработки.

## Критический путь и риски

Безопасный baseline → решения auth/data → API + сохранение → принятый Balance + медиа → пилот. Отдельный путь экзамена: досье/шкала/critical/практика → версия банка → полнота/хранение → документы. Полный редактор не является зависимостью первого Balance-пилота, но журнал публикаций обязателен уже в нём.

| Риск | Влияние | Мера / сигнал пересмотра |
|---|---|---|
| Досье отсутствует | Повторное проектирование требований | Отмечать решения как proposed, не публиковать спорный контент |
| Ключ не отозван | Доступ посторонних | P0 до внешнего запуска, владелец подтверждает отзыв |
| Бесплатный тариф спит/меняется | Нет гарантии непрерывного worker/диска | Реальный cold-start/restore тест; пересмотреть адаптер или provider без обязательного платного перехода |
| Медиа и переводы не приняты | Контентный путь длиннее разработки | Оценивать производство/ревью отдельно, готовить по модулям |
| Старые Sheets-итоги без ответов | Невозможно доказать прежнюю аттестацию | `legacy_result_unverified`, не генерировать основания задним числом |
| Несовершеннолетние/юрисдикция | Неочевидные обязанности по данным | Взрослый первый пилот; отдельное решение/проверка D-04 |
| Один разработчик и широкий scope | Большой разброс календарного срока | Проверяемые срезы, пересмотр оценки после фазы 1 |
| Опасная инструкция в разных языках | Риск для пользователя | Обязательное safety review каждой публикуемой версии/локали |

Итог каждой фазы — демонстрация и доказательства QA, а не только код/макеты. Незавершённая фаза не называется релизом.
