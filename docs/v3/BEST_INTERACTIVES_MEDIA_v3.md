## 2. Контракт ActivityVersion

Стабильный activity_id + неизменяемый version_id; competency IDs, lesson version, тип, цель, аудитория/локаль, prerequisite/evidence gate, media version IDs, допустимые состояния, allowlisted configuration, interaction policy, feedback/rationale, safe bounds, source/rights status и review decisions. Для каждого варианта ответа — stable ID, не номер позиции.

Статусы: draft → методическая проверка → safety review → перевод/проверка → approved → published/withdrawn. Сервер не выдаёт внутренние источники и скрытый ключ экзамена. Клиент выполняет только разрешённые переходы; payload редактора не содержит исполняемого JavaScript. Упражнение не может динамически подгрузить чужую защищённую лекцию как «медиа».

Сессия: start → inspect → act → submit → feedback → retry/finish. Записываются profile_id, activity_version, response, server time, revision и idempotency key. Offline-ответ, ещё не принятый сервером, отображается как несохранённый. Завершённый учебный ответ может улучшить LAB, но никогда не создаёт OBS/ASSESS автоматически.

В тренировке допускаются объяснение и повтор; в экзамене используется отдельная замороженная версия и политика раскрытия. Перенос одного и того же public training задания в защищённый экзамен требует решения о валидности измерения: известный ключ не должен маскироваться под независимую оценку.

## 3. Мультимедийная модель

Image/SVG: original asset + версии/ракурсы, alt, long description, подписи. Animation: те же принятые ключевые состояния; пауза/пошаговый режим/reduced-motion. Video: источник/авторство/лицензия, разрешение изображённых людей, сценарий/кадры, субтитры и текстовый эквивалент, ограничения применения. Audio: транскрипт и отсутствие необходимости слышать звук для ответа.

Обязательные метаданные: ID, название, учебная цель, B/E/S/T/SAFE/P, аудитория, язык, автор/источник, права и evidence, version/checksum, review status, file type/размер, текстовые альтернативы, lifecycle/withdrawal. Для детского видео — отдельное основание сбора, видимость, срок хранения и право удаления; по умолчанию такие видео не собираются в пилоте.

Необходимые ракурсы задаются brief, а не автоматическим отражением чужой картинки. У картинки нет права на публикацию, пока не подтверждены права на все исходные элементы. Генеративная графика тоже требует технической проверки: правдоподобная анатомия/геометрия не равна безопасной инструкции.

## 4. Доступность и поведение

Каждое drag-действие имеет кнопочную/клавиатурную альтернативу. Focus сохраняется после проверки; результат объявляется screen reader. Объекты подписаны, цвет не единственный признак, ошибки не зависят от реакции за секунды. Нельзя давать штраф за необходимость адаптации интерфейса. Время экзамена и доступные адаптации утверждаются отдельно.

На мобильном экран показывает одну цель, сцену и необходимые controls; объяснение раскрывается без перекрытия важных элементов. Автовоспроизведение/звук выключены по умолчанию. Если медиа недоступно, пользователь видит понятное состояние и альтернативу; отсутствие файла не выдаётся за пройденное упражнение.

## 5. Граница безопасности и приёмка

Любая физическая модель помечена «Учебное упрощение». Числовые предсказания динамики не входят в первую версию. Никаких медицинских диагнозов, настройки креплений или самостоятельных сложных манёвров через игровую механику.

Приёмка каждого интерактива: цель совпадает с competency; обе версии управления дают одинаковый смысл; правильный ответ/допустимые альтернативы приняты автором; feedback не содержит опасного совета; server save/retry не дублирует событие; provenance и локаль проверены; пользователь понимает границы. Реальная проверка на телефоне/клавиатуре и предметный reviewer обязательны до пилота.
