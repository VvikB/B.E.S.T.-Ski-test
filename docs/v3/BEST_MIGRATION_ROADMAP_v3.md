# B.E.S.T. Academy — перенос и поэтапная реализация v3

Статус: план на утверждение, исходные репозитории не менялись. Сначала права/методика/архитектура, затем самостоятельный контент и код. [Реестр](BEST_SOURCE_RIGHTS_REGISTER_v3.md), [архитектура](BEST_PLATFORM_ARCHITECTURE_v3.md), [решения](BEST_REVIEW_DECISIONS_v3.md).

## 1. Правила переноса

Код legacy, история и все 121 учебные записи сохраняются для контролируемого сравнения. Известные функции не удаляются и не заменяются маленьким demo. Одновременно сохранение материала не означает право публиковать его в новом продукте. Образовательные источники с неизвестными правами остаются в закрытом staging; новый публикуемый каталог разрабатывается самостоятельно.

Не копировать полный `best_data.json` в новый public content: он содержит access codes. Google service-account JSON не копируется вовсе. Исходный банк для сверки сохраняется с ограниченным доступом и provenance; его hash/порядок/occurrences фиксируются. Две записи ID 60 получают отдельные occurrence IDs. Скрытое удаление дубля запрещено; решение автора фиксирует новую редакцию с сохранением mapping.

Перенос исторических итогов из Sheets возможен только при разрешённом доступе и отдельной сверке. Без ответов/версии policy/практики такие итоги маркируются legacy_unverified; их нельзя задним числом превратить в подтверждённый новый допуск. Текущие users/FSM живут в памяти: их перенос при выключении нельзя обещать как гарантированный.

Это этапы, не обещание календарного срока. Оценку трудоёмкости v2 нельзя автоматически считать подтверждённой для 40 новых уроков, 36 схем и неизвестного объёма внешних источников. Отдельно оцениваются инженерия, дизайн/иллюстрации, методическое ревью/переводы и согласование прав. После получения файлов и утверждения первых briefs пересчитать backlog по фактическим единицам работы.

## 5. QA-матрица

- Контент: все IDs/ссылки/пререквизиты, версии/локали/права; критическая формулировка сверена с источником человеком. Никакого скрытого сокращения legacy.
- UI: все состояния Kids/Ski/Pro, `/start`/«Назад»/«Главная», старые callback, error/offline, телефон/keyboard/screen reader/reduced-motion.
- Доступ: профиль/возраст/представитель/назначения/сроки, независимый веб-вход, initData forgery/replay, прямой чужой URL/API, закрытый corpus.
- Данные: PostgreSQL migrations, restart между ответом/submit, конфликт revision, повтор import/update, backup/restore в отдельную БД и сверка чисел/ссылок.
- Экзамен: все утверждённые границы, mandatory/critical, незавершённость, время/пересдача, смена версии, невозможность подделать score/role/практику.
- Интеграции: настоящий test bot и test export отдельно от mocks; отказ Sheets не удаляет итог; доставка повторяется без дублей.
- Размещение: сон более заявленного периода, cold start, повторное создание процесса, сохранность диска/БД, правильный proxy/TLS, отсутствие второго poller/конфликтующего webhook.
- Правовая/методическая приёмка: права на каждый публикуемый элемент, новый собственный текст/сценарий, принятые критерии техники, ограничения по аудитории и реальный статус документов.

## 6. Риски и меры

Отсутствующие источники → нельзя завершить их обзор, добавить точные ссылки/лицензии; продолжать самостоятельное проектирование, зависимое ревью держать открытым. Неизвестные права → hold публикации, запрос разрешения либо самостоятельная новая разработка без копирования. Противоречивые инструкции → safety hold конкретной темы, не искусственный общий «всё проверено». Ключ Google → P0 до подключения интеграции. Бесплатный sleeping hosting → тесты wake/storage/restore и пересмотр доставки без обещания 24/7. Персональные данные детей → отдельный gate и минимум сбора. Отсутствие медиа → работа художника/автора, а не скриншоты школы. Рост scope → измеряемые маленькие срезы с явными ограничениями, без выдачи прототипа за полный релиз.
