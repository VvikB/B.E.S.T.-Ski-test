## Запуск на Mac, 10–15 минут на первоначальную настройку

Нужны Mac и iPhone в одной доверенной Wi-Fi сети, Python 3 и Homebrew. При отсутствии Homebrew установите его с официального brew.sh или попросите помочь с локальной настройкой; не выполняйте команды из случайных сайтов. Публичный туннель, домен и платный хостинг не нужны.

1. Используйте прежнюю распакованную D0.2: весь ZIP повторно скачивать не требуется. Скачайте [serve_https.py](../../academy-d01/tools/serve_https.py) и положите рядом с tools/serve_demo.py. Или обновите Git checkout этой ветки; при отсутствии dist выполните `npm ci && npm run build` в academy-d01.
Для скачивания одного файла без повторного ZIP, из папки приложения:

```sh
curl --fail --location https://raw.githubusercontent.com/VvikB/B.E.S.T.-Ski-test/academy-d02/academy-d01/tools/serve_https.py --output tools/serve_https.py
```

2. Откройте Terminal в папке приложения, где лежат `dist` и `tools`. Установите генератор локальных сертификатов:

```sh
brew install mkcert
```

3. Узнайте IPv4 Mac: Системные настройки → Wi-Fi → Подробнее → TCP/IP. Далее вместо `192.168.1.20` в обеих командах подставьте ваш адрес. Сертификат должен включать именно этот IP. Если IP изменится, выпустите сертификат заново. Ключи хранятся вне проекта:

```sh
mkdir -p "$HOME/.best-academy-tls"
chmod 700 "$HOME/.best-academy-tls"
mkcert -cert-file "$HOME/.best-academy-tls/demo.pem" -key-file "$HOME/.best-academy-tls/demo-key.pem" 192.168.1.20 localhost 127.0.0.1
chmod 600 "$HOME/.best-academy-tls/demo-key.pem"
cp "$(mkcert -CAROOT)/rootCA.pem" "$HOME/.best-academy-tls/BEST-local-test.crt"
```

`mkcert -install` на Mac не обязателен для проверки с телефона. Сертификат Mac Safari может требовать отдельного доверия на Mac; не обходите предупреждения на iPhone.

4. Через AirDrop передайте на iPhone **только BEST-local-test.crt**. Никогда не передавайте `rootCA-key.pem`, `demo-key.pem`, архив каталога CA или ключи старого проекта. Сверьте SHA256 корневого сертификата перед передачей, если канал вызывает сомнения: `shasum -a 256 "$HOME/.best-academy-tls/BEST-local-test.crt"`.
5. На iPhone откройте переданный сертификат → Настройки → Основные → VPN и управление устройством → загруженный профиль → установите сертификат. Затем Основные → Об этом устройстве → Доверие сертификатам → полное доверие именно этому локальному CA. Названия пунктов зависят от iOS. Не устанавливайте неизвестный профиль. Управляемый корпоративный iPhone может запрещать установку; не обходите это ограничение.

**Что означает доверие:** этот CA сможет подписывать сертификаты, которым доверяет телефон. Его закрытый ключ остаётся только на вашем Mac. Используйте CA только для локальной проверки; удалите профиль после теста. Это осознанное действие владельца, не автоматическая настройка телефона.

6. Из папки приложения запустите:

```sh
python3 tools/serve_https.py --host 0.0.0.0 --port 5443 --cert "$HOME/.best-academy-tls/demo.pem" --key "$HOME/.best-academy-tls/demo-key.pem"
```

Разрешите входящее подключение Python только в доверенной сети при запросе macOS. Не отключайте firewall целиком и не настраивайте проброс порта роутера. В Safari iPhone откройте **https://192.168.1.20:5443/lab** (с вашим IP). `localhost` на телефоне означает телефон, не Mac. В адресной строке не должно быть ошибки сертификата. Не вводите реальные данные. Сервер без авторизации: любой участник этой LAN потенциально может открыть демо.

7. После проверки Ctrl+C на Mac. На iPhone удалите локальный профиль сертификата и его доверие. Проверьте, что адрес больше не открывается. При необходимости удалите тестовые demo.pem/demo-key.pem из отдельной папки; корневой ключ mkcert не удаляйте без проверки, используется ли он другими вашими локальными проектами.

## Если не открывается

Оба устройства должны быть в одной сети без client isolation/гостевого режима. Проверьте актуальный IP, запущенный сервер и firewall. При ошибке сертификата проверьте SAN IP, время устройств и полное доверие CA; не используйте «продолжить небезопасно». Если Wi-Fi изолирует клиентов, минимальное решение — другая доверенная сеть, а не публичный туннель. Потеря WebGL должна оставлять доступным SVG; чёрный экран и перезагрузки — дефекты, которые нужно записать.
